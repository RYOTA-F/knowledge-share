# USER.md（あなた自身のプロフィール = ユーザーの分身）

OpenClawには、AIの人格を定義する `SOUL.md` と並んで、**ユーザー(あなた)のことをAIに教える** `USER.md` というファイルがあります。直訳すると「使い手」。AIに**あなたが何者か**を吹き込むファイルです。

> 📌 このページは [SOUL.md（AIの魂）](07_SOUL-md-詳細.md) と**対**になる内容です。あわせて読むと理解が深まります。

---

## USER.md とは何か

ChatGPTを使っていて、「毎回 “私は東京在住のエンジニアで…” と自己紹介するのが面倒」と感じたことはありませんか？

`USER.md` はそれを **永続的に解決** するファイルです。

- ファイル名: `USER.md`（固定）
- 場所: `~/.openclaw/workspace/USER.md`
- 中身: あなた自身の**プロフィール・背景・好み**を自然な言葉で書く
- 効果: **すべての会話でAIが自動的に参照する**

→ AIに「あなたの会話相手はこういう人です」という名刺を渡すイメージ。

---

## なぜ「ユーザーの分身」と呼ぶのか

OpenClawの設計思想では、会話の主役は**2人**います:

| ファイル | 誰のもの？ | 役割 | 人間に例えると |
|---|---|---|---|
| `SOUL.md` | **AI側** | AIがどう振る舞うか | AIの**人格・履歴書** |
| `USER.md` | **人間側** | ユーザーが何者か | あなたの**名刺・プロフィール** |
| `MEMORY.md` | 両者共有 | 会話で積み上がる事実 | 共同の**記憶ノート** |

SOUL.md だけだと、AIは「自分のキャラ」は知っていても「相手のこと」は知りません。USER.md があって初めて、**あなた専用の応答**が成立します。

---

## SOUL.md との対比

| 観点 | SOUL.md | USER.md |
|---|---|---|
| 主語 | 「私(AI)は〜」 | 「あなた(ユーザー)は〜」 |
| 定義するもの | AIの人格・口調・価値観 | ユーザーの属性・好み・背景 |
| 書き換え頻度 | ほぼ変えない | 生活の変化で更新 |
| 例 | 「丁寧な口調で話す」 | 「朝型なので早朝に通知OK」 |
| なかったら？ | 中立的なAIになる | 毎回自己紹介が必要 |

**イメージ**: SOUL.md は AI に渡す**履歴書**、USER.md はあなたが AI に渡す**名刺**。両方そろって初めて「会話」が噛み合います。

## USER.md の中身（実例）

### シンプルな例

```markdown
# User Profile

## 基本情報
- 名前: リョウタ
- 呼ばれ方: 「リョウタさん」でOK
- 居住地: 東京
- 職業: ソフトウェアエンジニア

## 生活リズム
- 朝型（6:00起床）
- 通知は7:00〜22:00の間だけOK
- 週末は家族時間なので緊急以外は連絡不要

## 好み
- 回答は結論から先に欲しい
- コード例は TypeScript で
- 長文より箇条書き
- 絵文字は少なめで

## 避けたいこと
- 「頑張ってください」的な励まし
- 推測での断定（「〜かもしれません」と明示して）
- 過剰な前置き
```

### 詳細な例（ビジネス向け）

```markdown
# User Profile: リョウタ

## アイデンティティ
- 氏名: 山田リョウタ
- 役職: プロダクトマネージャー
- 業界: SaaS / B2B
- 経験年数: 10年

## 専門領域
- プロダクト戦略、ロードマップ策定
- アジャイル開発、スクラム
- 決済まわりのドメイン知識あり

## コミュニケーション設定
- 日本語で対応
- 技術的な話はカジュアル英単語OK
- ミーティング要約は「決定事項 / TODO / 論点」の3セクション

## コンテキスト
- 家族構成: 妻・子ども1人
- 現在の目標: 新規事業の PMF を2026年Q3までに達成
- 抱えている課題: リソース配分、ステークホルダー調整

## 関係者の呼称
- 「弊社のCEO」= 佐藤さん
- 「例のプロジェクト」= Atlas プロジェクト
```

### ライフログ寄りの例

# User Profile

## 私について

- ドイツ語を初級レベルから勉強中

## USER.md でできること

### 1. 毎回の自己紹介が不要になる

AIが最初から「あなたは東京在住のエンジニアのリョウタさん」と知っているので、文脈の共有コストが一気に減ります。

### 2. パーソナライズされた応答

「今日の天気は？」→ 居住地を知っているので東京の天気を即答。「おすすめのレストラン」→ 好みを踏まえて提案。

### 3. 生活リズムに合わせた動作

「朝型」「夜は通知しないで」などを書いておけば、スケジュール実行(Heartbeat)が勝手に配慮してくれます。

### 4. 呼び方・敬称の統一

「リョウタさんと呼んで」「呼び捨てで」など、関係性の距離感を一発で設定できます。

### 5. 家族・同僚などの固有名詞の共有

「妻=ミカ」「上司=佐藤さん」と登録しておけば、「妻にメッセージを送って」で通じます。

---

## USER.md と MEMORY.md の違い

「どっちに書けばいいの？」と迷いがちな2つを整理します。

| 観点 | USER.md | MEMORY.md |
|---|---|---|
| 書くもの | **変わらない属性** | **積み上がる事実** |
| 書き方 | 自分で手書き | AIが自動で追記することも多い |
| 例 | 「東京在住」「エンジニア」 | 「2026-04-10 に Atlas の仕様変更を決定」 |
| 更新頻度 | 年に数回 | 日々追加される |

**使い分けルール**: 「**1年経っても変わらない情報 = USER.md**」「**時間とともに積み上がる情報 = MEMORY.md**」。

## 設定方法

### 1. ファイルを作る・編集する

メモ帳やVSCodeで直接編集できます。

```
~/.openclaw/workspace/USER.md
```

### 2. OpenClawを再起動

```bash
openclaw restart
```

次の会話から、新しいプロフィールが反映されます。

### 3. 試してみる

「私は誰？」「私の好みを踏まえて今日の予定を提案して」と送って、ちゃんと反映されるかチェック。

## ⚠️ セキュリティ上の注意

**USER.md は SOUL.md 以上にセンシティブ**です。なぜなら、**あなた個人の情報が詰まっている**から。

### ClawHavoc 事件で起きたこと

2026年1月の事件では、悪意あるスキルが `SOUL.md` だけでなく **`USER.md` からも個人情報を読み取って外部に送信**するケースがありました。具体的には:

- USER.md の「職場」「家族構成」「居住地」を抜き出してC2サーバに送信
- 「よく使うサービス」情報をもとにフィッシングメールを自動生成
- 「生活リズム」から不在時間を推測し、別の攻撃に利用

### 対策

1. **書いてよい情報の線引き**
   - ✅ OK: 名前、呼び方、職業、好み、生活リズム
   - ⚠️ 注意: 住所、電話番号、生年月日、勤務先の具体名
   - ❌ NG: パスワード、APIキー、クレジットカード、マイナンバー

2. **暗号化保存**
   ```bash
   # USER.md を含むワークスペースをGPGで暗号化
   gpg -c ~/.openclaw/workspace/USER.md
   ```

3. **アクセス権限の制限**
   ```bash
   chmod 600 ~/.openclaw/workspace/USER.md  # 自分以外読み取り不可
   ```

4. **Gitで変更履歴を追う**
   ```bash
   cd ~/.openclaw/workspace
   git add USER.md
   git commit -m "Initial user profile"
   ```
   `git diff` で不審な書き換えを検知できます。

5. **スキルの権限を絞る**
   怪しいスキルが `USER.md` を読めないよう、`~/.openclaw/permissions.yml` でスキルごとの読み取り権限を制御しましょう。

## よくある質問

### Q. USER.md は必須ですか？

**A. いいえ。** 無くても OpenClaw は動きます。ただし、**個人化された応答を受けたいなら強く推奨**します。

### Q. SOUL.md と USER.md はどちらを先に書くべき？

**A. USER.md を先に。** まず「あなたが何者か」を AI に伝えてから、「AIがどう振る舞うか(SOUL)」を決める方が自然です。名刺交換 → 会話スタイルの順ですね。

### Q. 家族・会社の他の人の情報も書いていい？

**A. 注意が必要。** 他人の個人情報を書く場合は、その人の同意を取るか、匿名化(「妻」「上司A」など)しましょう。プライバシー侵害のリスクがあります。

### Q. プロファイルを切り替えたい（仕事用・プライベート用）

**A.** SOUL.md と同様、プロファイル機能で切り替え可能です。

```bash
openclaw profile create work
openclaw profile create personal
openclaw profile switch work
```

プロファイルごとに独立した `USER.md` と `SOUL.md` を持てます。

### Q. AIが USER.md を無視することはある？

**A. あります。** 特に長文になると参照が甘くなります。**重要な情報は冒頭に書く**、**箇条書きで整理する**のがコツです。

---

## 書き方のコツ

### ✅ 良い書き方

- **構造化する**: セクション(基本情報/好み/避けたいこと)を分ける
- **具体的に**: 「朝型」より「6:00起床、22:00就寝」
- **主語を明確に**: 「私は〜」と書く
- **定期的に見直す**: 引っ越し、転職、価値観の変化で更新

### ❌ 避けたい書き方

- **機密情報を書く**: パスワードや暗証番号は絶対NG
- **冗長な自伝**: 3,000行の自分史は AI も追えない
- **矛盾する情報**: 「カジュアル希望」と「フォーマル希望」を同時に書く
- **古い情報の放置**: 3年前の勤務先などを更新せず残す
