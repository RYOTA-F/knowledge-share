# カスタマイズ完全ガイド

OpenClawの真価は **自分好みに作り変えられる** こと。ここでは「何を、どこで、どうやってカスタマイズできるか」を1ページにまとめました。

---

## カスタマイズできる8つの領域

| # | 領域 | 何ができる？ | 難易度 |
|---|---|---|---|
| 1 | **SOUL.md** | AIの性格・口調を変える | ★☆☆ |
| 2 | **MEMORY.md** | 覚えてほしい情報を書く | ★☆☆ |
| 3 | **SKILL.md** | やってほしい仕事を追加 | ★★☆ |
| 4 | **LLMモデル** | 脳みその種類・組み合わせ | ★★☆ |
| 5 | **メモリプラグイン** | 記憶の保存先を変える | ★★☆ |
| 6 | **チャネル** | 接続するアプリを増やす | ★★☆ |
| 7 | **スケジュール** | 定期実行ジョブを設定 | ★★☆ |
| 8 | **ツール権限** | できること・できないことを制限 | ★★★ |

---

## 1. SOUL.md — AIの性格カスタマイズ

`SOUL.md` は AIの**人格設定ファイル**です。詳細は [SOUL.md 詳細](07_SOUL-md-詳細.md) を参照。

### 場所

```
~/.openclaw/workspace/SOUL.md
```

### 例

```markdown
# AI Soul

## 名前
クロエ

## 話し方
- 丁寧な「です・ます」調
- 結論から先に話す
- 絵文字は1メッセージに1個まで

## やってはいけないこと
- 推測で答えない
- 政治・宗教の話題は避ける
```

### 反映方法

```bash
openclaw restart
```

---

## 2. MEMORY.md — 記憶の事前登録

`MEMORY.md` は AIの**長期記憶ファイル**です。自動で増えていきますが、**手動で書き込んでもOK**。

### 場所

```
~/.openclaw/workspace/MEMORY.md
```

### 例: 自分のプロフィールを覚えさせる

```markdown
# Memory

## ユーザー情報
- 名前: 田中太郎
- 職業: バックエンドエンジニア(NestJS専門)
- タイムゾーン: Asia/Tokyo

## プロジェクト
- メインプロジェクト: ECサイトリニューアル(Q1〆切)
- 使用技術: NestJS, PostgreSQL, GCP

## 好み
- 朝のブリーフィング: 7:30に Telegram
- 返信不要メール: メルマガ・プロモーション
```

### ⚠️ 注意

- **APIキーやパスワードは絶対に書かない**(ブラックボックスじゃないので人にも見える)
- 機密情報は別の安全な場所(Vault等)で管理

## 3. SKILL.md — 新しい仕事の追加

詳細は [SKILL.md の書き方](05_SKILL-md-詳細.md) を参照。

### 3つの追加方法

#### A. ClawHub からインストール(一番簡単)

```bash
# 検索
openclaw skills search "weather"

# インストール
openclaw skills install @community/notion-sync

# 一覧
openclaw skills list
```

#### B. 自分で書く

```
~/.openclaw/skills/my-skill/SKILL.md
```

を作成し、`openclaw restart` で読み込み。

#### C. CLI で追加

```bash
openclaw skills add ./path/to/SKILL.md
```

### スキル管理コマンド

```bash
openclaw skills list                # 一覧
openclaw skills show email-send     # 詳細
openclaw skills enable email-send   # 有効化
openclaw skills disable email-send  # 無効化
openclaw skills remove email-send   # 削除
```

## 4. LLMモデルのカスタマイズ

詳細は [LLMモデルとAPI](02_LLMモデルとAPI.md) を参照。

### A. プロバイダーの設定

```bash
# Anthropic Claudeを使う
openclaw config set provider.default anthropic
openclaw config set anthropic.apiKey YOUR_API_KEY
openclaw config set anthropic.model claude-sonnet-4-6

# OpenAI GPTを使う
openclaw config set provider.default openai
openclaw config set openai.apiKey YOUR_API_KEY
openclaw config set openai.model gpt-5

# Ollama(ローカル)を使う
openclaw config set provider.default ollama
openclaw config set ollama.model llama3
```

### B. タスクごとに別モデルを使い分ける(モデルルーティング)

OpenClawの**強力な機能**:タスクの種類によって自動でモデルを切り替えられます。

```yaml
# config.yaml の例
routing:
  default: claude-haiku-4-5      # 普段は安いモデル
  coding: claude-sonnet-4-6      # コードの時はSonnet
  reasoning: claude-opus-4-6     # 重要な判断はOpus
  embedding: text-embedding-3-small  # 検索用
```

→ **コスト最適化**の鍵。軽い作業に重いモデルを使わずに済む。

### C. 設定ファイル

```
~/.openclaw/config/providers.json
```

を直接編集することもできます。

## 5. メモリプラグインの切り替え

OpenClawは**メモリの保存先・検索方式を変えられます**。デフォルトはローカル、用途に応じて切り替え可能。

### 5つの選択肢

| プラグイン | 保存先 | 意味検索 | 同期 | 難易度 |
|---|---|---|---|---|
| **memory-core**(デフォルト) | ローカル `MEMORY.md` | ❌ | ❌ | ★ |
| **MemOS Cloud** | クラウド | ✅ | ✅ | ★★ |
| **Supermemory** | クラウド | ✅ | ✅ | ★★ |
| **Cognee** | ハイブリッド + 知識グラフ | ✅ | ✅ | ★★★ |
| **Mem0** | クラウド | ✅ | ✅ | ★★ |

### インストール例

```bash
# Supermemory に切り替え
openclaw plugins install supermemory
openclaw plugins configure supermemory

# 元に戻す
openclaw plugins install memory-core
```

### 選び方

- **個人・シンプル重視** → memory-core
- **複数デバイス同期したい** → MemOS Cloud / Supermemory
- **「あのとき話してた○○」を思い出させたい** → Supermemory(セマンティック検索強い)
- **大量のコンテキストを構造化したい** → Cognee
- **長期的なユーザーモデリング** → Mem0

### セマンティック検索を有効にする(memory-core でも可能)

埋め込みモデル(embedding)を設定すれば、デフォルトのmemory-coreでも意味検索ができます。

```bash
# OpenAI Embeddingsを使う
openclaw config set embeddings.provider openai
openclaw config set embeddings.model text-embedding-3-small

# ローカルOllamaを使う
openclaw config set embeddings.provider ollama
openclaw config set embeddings.model nomic-embed-text
```

## 6. チャネル(接続するメッセージアプリ)の追加

OpenClawは50以上のメッセージプラットフォームに対応。複数同時接続OK。

### 追加できるチャネル

- WhatsApp / Telegram / Signal / iMessage(BlueBubbles)
- Slack / Discord / Microsoft Teams / Google Chat
- Matrix / Zalo など

### 追加の流れ(Telegram例)

```bash
# 1. Telegramの@BotFatherでBotを作る
# 2. APIトークンを取得
# 3. OpenClawに設定
openclaw channel add telegram --token YOUR_BOT_TOKEN

# 4. ペアリングコードで接続承認
# 5. 確認
openclaw channel list
```

### マルチチャネル運用

```yaml
# 例: 用途別に使い分け
channels:
  - name: telegram-personal
    type: telegram
    purpose: 個人の通知・タスク
  - name: slack-work
    type: slack
    purpose: 仕事関連
  - name: discord-team
    type: discord
    purpose: チーム連携
```

## 7. スケジュール(定期実行)のカスタマイズ

詳細は [スケジュール実行](08_スケジュール実行.md) を参照。

### 設定方法は2通り

#### A. 自然言語で(一番楽)

```
ユーザー: 「毎朝7時30分に天気予報と今日の予定をTelegramに送って」
OpenClaw: 「了解しました。設定完了です」
```

#### B. CLIで直接

```bash
openclaw schedule add \
  --name "morning-briefing" \
  --cron "30 7 * * *" \
  --skill "daily-briefing" \
  --channel telegram
```

### cron書式の早見表

| 書き方 | 意味 |
|---|---|
| `30 7 * * *` | 毎日 7:30 |
| `0 9,15 * * 1-5` | 平日の 9時 と 15時 |
| `0 9 * * 1` | 毎週月曜 9:00 |
| `*/15 * * * *` | 15分ごと |
| `0 0 1 * *` | 毎月1日 0:00 |

### 失敗時のリトライ設定

```yaml
name: my-task
schedule: "0 9 * * *"
retry:
  attempts: 3       # 3回まで再試行
  delay: 300        # 5分ごと
on_failure:
  notify: telegram
  message: "タスク {name} が失敗しました"
```

### 管理コマンド

```bash
openclaw schedule list                  # 一覧
openclaw schedule pause morning-briefing  # 一時停止
openclaw schedule resume morning-briefing # 再開
openclaw schedule remove morning-briefing # 削除
openclaw schedule history               # 実行履歴
```

## 8. ツール権限のカスタマイズ(セキュリティ重要)

OpenClawは**何ができるかを制限できます**。これが最大のセキュリティ対策。

### プロファイル(プリセット)で簡単設定

```bash
openclaw profile use minimal     # 最小限(読み取りのみ)
openclaw profile use messaging   # メッセージング系のみ
openclaw profile use coding      # 開発系
openclaw profile use full        # 全部(注意!)
```

### 個別に許可・拒否

```yaml
# config.yaml
tools:
  allow:
    - browser
    - file.read
    - email.send
  deny:
    - exec          # シェル実行は禁止
    - file.write    # 書き込み禁止
    - file.delete   # 削除禁止
```

### 優先ルール

**許可と拒否が競合した場合は、拒否が優先**されます。安全側に倒れる設計。

### サンドボックスの強度設定

| 設定 | 説明 | 推奨シーン |
|---|---|---|
| `Off` | サンドボックスなし | 個人開発のみ(本番不可) |
| `Non-main`(デフォルト) | グループチャットだけ隔離 | 一般的な個人利用 |
| `All` | 全ツール呼び出しを隔離 | 高セキュリティ要件 |

```bash
openclaw config set sandbox.mode all
```

### グループ単位の権限管理

複数ユーザーがいる場合、グループごとに権限を設定可能。

```yaml
groups:
  - name: family
    profile: minimal
    members: [user1, user2]
  - name: developers
    profile: coding
    members: [user3]
```

## カスタマイズの全体像(まとめ図)

```
~/.openclaw/
├── config/                  ← 設定ファイル
│   ├── gateway.json         # Gateway全体設定
│   ├── providers.json       # LLMモデル設定
│   └── channels.json        # メッセージアプリ設定
│
├── workspace/               ← 個人データ
│   ├── SOUL.md              ← 性格(あなたの好み)
│   ├── MEMORY.md            ← 記憶(積み重なる)
│   ├── sessions/            ← 日々の会話ログ
│   └── user-profile.md      ← ユーザープロファイル
│
└── skills/                  ← スキル群
    ├── bundled/             # 最初から入ってる
    ├── managed/             # ClawHubから入れたもの
    └── custom/              ← 自作スキル(SKILL.md)
```

## おすすめのカスタマイズ順

OpenClawを使い始めたら、この順番で設定を進めるとスムーズです:

### Step 1(初日)— 基本設定

1. ✅ LLMプロバイダーを設定(Anthropic Claudeなど)
2. ✅ 1つのチャネルを接続(Telegramがおすすめ)
3. ✅ プロファイルを `messaging` に設定(安全側に)
4. ✅ 月額上限を設定する(暴走防止)

### Step 2(1週間以内)— 個性付け

5. ✅ `SOUL.md` を書く(性格・口調)
6. ✅ `MEMORY.md` に自分のプロフィールを書く
7. ✅ ビルトインスキルを試す(メール、天気)

### Step 3(慣れてきたら)— 自動化

8. ✅ 朝のブリーフィングをスケジュール化
9. ✅ 自分のSKILL.mdを1つ書いてみる
10. ✅ ClawHubから1つスキルを入れてみる(中身チェック必須)

### Step 4(さらに先)— 最適化

11. ✅ モデルルーティングでコスト削減
12. ✅ メモリプラグインを Supermemory などに変更
13. ✅ 複数チャネルを使い分け
14. ✅ 自分のスキルを ClawHub に公開

## カスタマイズ時のチェックリスト

何かを変えたら、必ず確認:

- [ ] `openclaw status` でGatewayが起動しているか
- [ ] `openclaw config show` で設定が反映されているか
- [ ] `openclaw logs --tail 50` でエラーが出ていないか
- [ ] テストメッセージで動作確認
- [ ] `openclaw usage stats` でコスト監視
- [ ] バックアップを取った(`cp -r ~/.openclaw/workspace ~/backup/`)

---

## まとめ

OpenClawのカスタマイズは **「8つのレイヤー」** を組み合わせるパズル:

1. **SOUL.md** = 性格
2. **MEMORY.md** = 記憶
3. **SKILL.md** = 仕事
4. **LLMモデル** = 脳みそ
5. **メモリプラグイン** = 記憶の保管庫
6. **チャネル** = 連絡手段
7. **スケジュール** = 自動実行のタイミング
8. **権限** = 安全装置

全部いじる必要はなく、**今の自分に必要なところだけ少しずつ**変えていけばOK。設定ファイルはすべてMarkdownやJSONなので、後から見返せて、Gitでバックアップもできます。
